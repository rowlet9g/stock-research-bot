# FORGETMENOT 프로젝트 계획

## 1. 프로젝트 정의

FORGETMENOT은 보유종목과 관심종목을 대상으로 가격, 거래량, 공시, 재무,
거시경제, 투자 가설을 함께 추적하는 개인용 주식 리서치 및 토론 도구다.

이 프로젝트의 핵심은 가격을 맞히는 것이 아니라 다음 질문에 반복적으로 답하는 데 있다.

- 현재 시장과 종목에서 확인된 사실은 무엇인가?
- 과거에 기록한 투자 가설은 아직 유효한가?
- 투자 가설과 충돌하는 새로운 증거가 있는가?
- 포트폴리오에 과도한 국가, 섹터, 통화, 종목 노출이 있는가?
- 추가 판단 전에 확인해야 할 정보는 무엇인가?

## 2. 제품 원칙

### 2.1 반드시 지킬 원칙

- 계산 가능한 값은 코드가 계산한다.
- AI는 계산 결과와 출처가 명시된 자료를 해석한다.
- 모든 분석 결과는 사실, 해석, 반론, 확인 질문을 구분한다.
- 모든 외부 데이터에는 출처, 기준시각, 수집시각을 기록한다.
- 데이터가 없거나 오래되었으면 그 사실을 명시한다.
- 하나의 데이터 공급자만으로 중요한 결론을 확정하지 않는다.
- 예측은 단일 목표가격이 아니라 시나리오, 확률, 근거, 무효화 조건으로 표현한다.
- 자동 주문과 비공식 증권사 로그인 자동화는 구현하지 않는다.

### 2.2 비목표

- 자동 매수 및 자동 매도
- 수익률 보장
- 근거 없는 종목 추천
- 공식 지원이 없는 증권사 화면 스크래핑
- 초단타매매용 실시간 시세 시스템
- 검증되지 않은 뉴스나 소셜미디어 정보의 단독 사용

## 4. 데이터 출처 정책

### 4.1 출처 우선순위

1. 규제기관, 거래소, 중앙은행, 기업 공식 IR 자료
2. 계약과 사용 조건이 명확한 데이터 API
3. 신뢰 가능한 뉴스 제공자
4. 비공식 또는 무보증 데이터는 보조 자료로만 사용

### 4.2 초기 데이터 공급자

| 범위 | 우선 공급자 | 용도 | 상태 |
| --- | --- | --- | --- |
| 국내 공시/재무 | OpenDART | 공시, 기업개황, 재무정보, 기업코드 | 기업코드, 공시 원본과 전체 재무제표 구현 |
| 국내 식별자/일별 ETP | KRX Open API | 종목기본정보, ETF/ETN 일별정보 | 구현 및 운영키 검증 완료 |
| 해외 시세 | Yahoo Finance | 초기 가격 스냅샷 | 임시 구현 |
| 미국 공시/재무 | SEC EDGAR | 10-K, 10-Q, 8-K, XBRL | 미구현 |
| 미국 거시경제 | FRED | 금리, 물가, 고용, 경기지표 | 미구현 |
| 기업 뉴스 | 기업 IR/프레스룸/RSS | 공식 기업 발표 | 미구현 |
| 증권계좌 | 미래에셋 XLSX | 보유종목, 평단가, 거래내역 | 거래내역 import 구현 |

Yahoo Finance 데이터는 공식적인 실시간 시세 계약이나 가용성 보장이 없으므로,
중요 판단의 단일 근거로 사용하지 않는다.

미래에셋증권 계좌 연동은 일반 개인 개발자용 공식 조회 API 제공 여부가 확인될
때까지 CSV 가져오기를 기본 방식으로 사용한다.

### 단계 0. 기준선 고정

목표: 현재 코드를 재현 가능한 출발점으로 만든다.

작업:

- Go를 주 구현으로 명시한다.
- Python은 레거시 기준 구현으로 표시한다.
- 기본 개발 및 검증 명령을 문서화한다.
- 현재 Go 포팅 커밋을 원격 저장소에 반영한다.
- Windows와 Codex 환경에서 Go 캐시 및 텔레메트리 경고 처리 방법을 정리한다.

완료 기준:

- 새 환경에서 README만 보고 빌드와 테스트를 수행할 수 있다.
- `go test ./...`와 `go vet ./...`가 오류 없이 끝난다.
- Git 작업 트리가 깨끗하다.

기준선 검증 기록:

- 환경: Windows/amd64, Go 1.26.3
- 모듈 최소 버전: Go 1.22
- `go build ./...`, `go test ./...`, `go vet ./...` 통과
- `gofmt -l cmd internal`에서 미포맷 파일 없음
- Yahoo Finance 정상 응답과 네트워크 차단 시 부분 실패 처리를 각각 확인

### 단계 1. Go 데이터 기반 안정화

목표: 외부 데이터를 손실 없이 수집하고 검증 가능한 형태로 표현한다.

작업:

- `PriceBar`에 날짜, 통화, 출처, 수집시각을 추가한다.
- Yahoo의 종가와 거래량을 동일 타임스탬프 기준으로 정렬한다.
- Yahoo와 DART 요청에 독립적인 timeout을 적용한다.
- CSV 필수 헤더와 각 행을 검증한다.
- CLI에 사람이 읽는 출력과 JSON 출력을 분리한다.
- 외부 API 응답은 fixture 기반 테스트로 검증한다.
- 네트워크 오류, 빈 데이터, 부분 데이터 상태를 구분한다.

완료 기준:

- 가격과 거래량의 날짜 정렬을 테스트로 보장한다.
- 모든 출력에 데이터 기준시각과 출처가 표시된다.
- 외부 네트워크 없이 단위 테스트가 통과한다.
- 실패 원인이 사용자 입력, 공급자 오류, 데이터 없음으로 구분된다.

구현 기록:

- `PriceBar`, `DataStatus`, `SourceMetadata` 도메인 모델 추가
- Yahoo timestamp 기준 종가/거래량 정렬 및 부분 데이터 경고 추가
- Yahoo와 OpenDART의 독립 timeout과 공통 공급자 오류 분류 추가
- OpenDART 결과에서 API 키를 제외한 안전한 출처 URL 기록
- 관심종목 CSV 필수 헤더, 필수 값, 중복 ticker 검증 추가
- CLI `-output text|json` 형식과 구조화된 `issues` 추가
- Yahoo, OpenDART, watchlist, prompt, CLI fixture/단위 테스트 추가

### 단계 2. SQLite와 투자 기록

목표: 관심종목, 보유내역, 거래, 투자 가설을 영구 저장한다.

작업:

- SQLite 스키마와 migration 체계를 만든다.
- 관심종목 CRUD를 구현한다.
- 미래에셋 거래내역 XLSX 형식 탐색 및 import mapping을 구현한다.
- Position과 Trade를 분리해 저장한다.
- Thesis, 무효화 조건, 예상 보유기간, 확인 지표를 저장한다.
- 중복 CSV import를 막는 idempotency 키를 설계한다.

완료 기준:

- 앱을 종료하고 다시 실행해도 데이터가 유지된다.
- 동일 거래내역을 두 번 가져와도 중복 저장되지 않는다.
- 한 종목의 보유내역, 거래내역, 투자 가설을 함께 조회할 수 있다.
- 비밀정보와 계좌 원본 파일이 Git에 포함되지 않는다.

구현 기록:

- CGo가 필요 없는 `modernc.org/sqlite v1.36.1`을 Go 1.22 호환 버전으로 고정
- checksum 검증을 포함한 embedded migration 체계 추가
- 관심종목 upsert/list/delete repository 추가
- Position, Trade, Thesis 분리 저장과 포트폴리오 통합 조회 추가
- 금액과 수량을 소수점 8자리 고정 정밀도 정수로 저장
- 파일 hash와 거래 `external_id` 기반 idempotency 추가
- 정규화 거래 CSV import와 transaction rollback 추가
- DB 재시작, 반복 import, rollback, CLI 전체 흐름 통합 테스트 추가
- DB 및 개인 CSV를 Git 제외 대상으로 추가
- 미래에셋 거래내역 XLSX의 실제 헤더와 132개 원장 행 구조 검증
- 입출고/입출금 이중 원장 중 4개 체결 유형만 선택하는 adapter 추가
- 거래금액과 수량 기반 단가 계산, 날짜 정밀도와 세금 미제공 상태 저장
- 원본 거래번호를 대체하는 결정론적 SHA-256 거래 식별자 추가
- 검증된 로컬 종목 alias cache와 Yahoo 검색 fallback 추가
- 합성 XLSX fixture 기반 adapter 및 CLI 반복 import 테스트 추가

### 단계 3. 공식 데이터 공급자 확장

목표: Yahoo 의존도를 낮추고 국내외 공식 자료를 확보한다.

작업:

- OpenDART 기업 고유번호 전체 목록 동기화를 구현한다.
- 공시 원문과 정기보고서 재무정보를 수집한다.
- KRX 일별 주식 및 지수 데이터를 추가한다.
- SEC EDGAR 제출내역과 company facts를 추가한다.
- FRED 주요 거시경제 시계열을 추가한다.
- 기업 IR 및 프레스룸은 RSS 또는 공식 피드가 있을 때만 자동 수집한다.
- 공급자별 호출 제한, 재시도, 캐시 정책을 정의한다.

현재 구현:

- OpenDART `corpCode.xml` ZIP/XML 다운로드와 엄격한 fixture 파싱
- 기업 8자리 고유번호와 6자리 대문자 영숫자 종목코드 검증
- SQLite 전체 스냅샷 upsert, 과거 행 비활성 보존, 중복 실행 지원
- 저장된 국내 종목의 `dart_corp_code` 자동 연결
- 빈 목록, 손상 목록, 중복 식별자에서 기존 데이터 보존
- API 키가 제거된 출처 URL과 원본 변경일, 수집시각 저장
- HTTP 429/5xx 최대 3회 시도와 OpenDART 전용 TLS 호환 설정
- KRX 유가증권, 코스닥, 코넥스 종목기본정보 adapter와 fixture 파싱
- KRX ETF, ETN 일별매매정보 기반 식별자와 증권 유형 보완
- KRX 6자리 단축코드와 12자리 표준코드의 독립 검증 및 저장
- 보통주, 우선주, ETF, ETN, 기타 지분증권의 명시적 유형 분류
- 저장된 원화 종목 ticker와 KRX 단축코드의 정확 일치 매핑
- KRX 보통주와 OpenDART 대표 종목코드의 교차 매핑 및 충돌 집계
- 데이터셋별 부분 실패 저장, 빈 스냅샷 거부, 과거 행 비활성 보존
- KRX 인증키 header 처리, 429/5xx 재시도, 출처 URL에서 인증키 제외
- OpenDART 공시검색의 전체 페이지 수집과 엄격한 응답 필드 검증
- 공시 접수번호 기반 SQLite upsert와 반복 실행 중복 방지
- 접수일, 법인구분, 제출인, 비고, 뷰어 URL, 출처와 수집시각 저장
- 기업별 부분 실패를 격리하는 `dart-disclosure-sync` CLI
- 저장된 최신 공시를 조회하는 `dart-disclosure-list` CLI
- OpenDART 공시서류원본파일 ZIP 다운로드와 엄격한 경로, CRC, 크기 검증
- 접수번호와 원본 SHA-256 기반 로컬 파일 저장, SQLite 원본 메타데이터 저장
- 압축 해제된 파일명과 내용 해시 기반 논리 버전 판정
- 동일 내용의 ZIP 재압축을 새 버전으로 오인하지 않는 파일 재사용
- 문서별 부분 실패를 격리하는 `dart-document-sync`와 버전 조회 CLI
- OpenDART 단일회사 전체 재무제표 CFS/OFS adapter와 엄격한 계정 검증
- 재무 금액의 부호 포함 정수 문자열 정규화와 응답 순서 독립 내용 해시
- 사업연도, 보고서 코드, CFS/OFS별 현재 버전과 정정 이력 보존
- 기업과 재무제표 구분별 부분 실패를 격리하는 sync/list CLI
- 표준계정 ID와 재무제표 구역 기반 핵심 재무지표 매핑
- 증감률, 영업이익률, 순이익률, 부채비율, 유동비율의 정수 기반 계산
- 중복 계정, 결측치와 0 이하 비교 기준을 명시적 상태로 반환하는 metrics CLI
- 저장된 최신 공시와 최신 현재 재무제표를 선택하는 조회
- 포트폴리오, Yahoo 가격, 공시와 재무정보를 결합하는 `analysis-snapshot` CLI
- 입력 스키마·규칙 버전과 생성시각 독립 `input_sha256` 기록
- 공급자 또는 저장 데이터 부분 실패의 격리와 `partial` 원인 기록
- 재무 임계값, 가격 신호, 포지션·가설 품질과 공시 제목의 결정론적 위험 규칙
- 사실, 가능한 해석, 확인 질문과 출처 증거를 분리한 위험 평가 결과
- 규칙 설정·버전과 중복 억제용 finding fingerprint를 반환하는 `risk-assess` CLI
- 동일 입력 해시의 스냅샷과 위험 평가를 사용하는 통합 리서치 프롬프트
- 외부 데이터 필드의 명령 취급 금지와 계산값 재추정 금지를 명시한 프롬프트 경계
- OpenAI API 없이 ChatGPT Plus에 붙여넣는 `research-brief` CLI
- 거래기간 매수·매도 순증과 저장된 현재 포지션의 읽기 전용 대조
- 기초잔고가 없을 때 기간 순증을 현재 보유수량으로 오인하지 않는 데이터 계약
- 지원하지 않는 거래 유형과 역산 기초잔고를 명시하는 `position-reconcile` CLI
- 현재 포지션 CSV의 전체 검증과 단일 트랜잭션 일괄 저장
- 동일 포지션 스냅샷 재입력 시 불필요한 갱신을 막는 멱등 `positions-import` CLI

- 데이터 공급자 장애가 다른 공급자의 수집을 중단시키지 않는다.

### 단계 4. 분석 엔진

목표: AI 없이도 재현 가능한 분석 결과를 만든다.

작업:

- 가격 추세, 거래량, 변동성, 낙폭을 계산한다.
- 국가, 섹터, 통화, 단일종목 집중도를 계산한다.
- 환율을 반영한 원화/외화 손익을 분리한다.
- 공시 위험 규칙을 정의한다.
- 투자 가설과 신규 Evidence를 연결한다.
- 분석 결과에 입력 데이터 버전과 규칙 버전을 기록한다.

완료 기준:

- 동일 입력과 동일 규칙 버전은 동일 결과를 만든다.
- 모든 경고에 계산식 또는 근거 데이터가 연결된다.
- 사실과 해석이 구조적으로 분리된다.
- 임계값은 코드에 흩어두지 않고 설정으로 관리한다.

### 단계 5. 스케줄러와 알림

목표: 중요한 변화가 발생했을 때 사용자가 먼저 확인할 수 있게 한다.

작업:

- 장 마감, 일간, 주간 작업 스케줄을 정의한다.
- Telegram Bot 알림을 구현한다.
- 이메일 일간/주간 보고서를 구현한다.
- 중복 알림 억제와 재전송 정책을 구현한다.
- 심각도와 quiet hours를 지원한다.
- 알림에서 근거와 상세 분석 링크를 제공한다.

완료 기준:

- 테스트 알림과 실제 조건 알림을 구분할 수 있다.
- 동일 사건으로 알림이 반복 전송되지 않는다.
- 발송 성공, 실패, 확인 상태가 저장된다.
- 민감한 계좌정보가 알림 본문에 불필요하게 노출되지 않는다.

### 단계 6. 대화형 분석

목표: ChatGPT Plus에서 포트폴리오와 투자 가설을 근거 기반으로 질의한다.

작업:

- Go HTTP API를 읽기 전용으로 먼저 구현한다.
- API 인증, rate limit, 감사 로그를 추가한다.
- OpenAPI schema를 작성한다.
- ChatGPT 커스텀 GPT Actions에 연결한다.
- API 응답에 사실, 출처, 기준시각을 포함한다.
- 대화에서 생성된 새로운 가설이나 기록의 쓰기 기능은 별도 승인 흐름으로 분리한다.

완료 기준:

- "내 포트폴리오에서 오늘 가장 중요한 변화"에 출처와 함께 답할 수 있다.
- "매수 당시 가설이 아직 유효한가"에 지지/반박 Evidence를 함께 제시한다.
- 데이터가 부족하면 추측하지 않고 부족한 항목을 명시한다.
- 읽기 API와 쓰기 API의 권한이 분리된다.

### 단계 7. 전용 UI

목표: 대화 외에도 포트폴리오 상태를 빠르게 관측한다.

작업:

- 먼저 반응형 웹 또는 PWA를 검토한다.
- 관심종목, 보유종목, 공시, 알림, 투자일지 화면을 구현한다.
- 전용 모바일 앱이 필요한지 실제 사용 결과로 결정한다.
- 모바일 앱을 선택하면 FCM을 통해 푸시 알림을 제공한다.

완료 기준:

- 휴대폰에서 핵심 상태와 알림 상세를 확인할 수 있다.
- 대화 없이도 데이터 최신성과 주요 위험을 파악할 수 있다.
- UI 구현이 분석 엔진의 계산 로직을 복제하지 않는다.

### 단계 8. 예측 및 사후 검증

목표: 검증 가능한 시나리오 예측을 제공한다.

작업:

- 상승, 중립, 하락 시나리오를 정의한다.
- 각 시나리오에 확률, 기간, 근거, 무효화 조건을 기록한다.
- walk-forward 방식으로 과거 데이터에서 검증한다.
- 적중률뿐 아니라 calibration, drawdown, false-positive를 측정한다.
- 모델과 규칙 변경 이력을 보존한다.

완료 기준:

- 미래 정보를 학습이나 검증에 누출하지 않는다.
- 예측 결과와 실제 결과를 자동 비교한다.
- 정확도와 불확실성을 함께 표시한다.
- 검증 결과가 없는 예측은 사용자에게 명확히 표시한다.
